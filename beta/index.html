TickerTouch — Calendar Hours

Version 1.7.1 — this is not the default firmware.

Two things could put a calendar entry exactly one hour out, and this build addresses both.

The zone the feed writes in. A calendar can stamp its times in its own timezone (DTSTART;TZID=America/Denver:...). That parameter was being thrown away, so a calendar set to a different zone than the panel read an hour or three out. It is now read and converted properly.

The panel's own zone. That still comes from an IP lookup, which is wrong if your address resolves somewhere else. Settings now has a Timezone dropdown, and /diag has a Time card that states the zone in use, the offset being applied, and what the clock and UTC each read.

Keep your settings: this installer asks whether to erase the device before flashing. Leave erase off — erasing wipes the WiFi credentials, city and league selection, both calendar URLs and the icon choices.

What to check after installing
  • Open /diag: the Time card should name your zone and the right offset.
  • If that zone is not yours, set it in Settings → Display → Timezone and restart.
  • Open /cal: each block now shows the zone it was written in, if the feed names one — the quickest way to see which calendar is causing the shift.
  • Calendar entries should now match your phone, in both calendars.

Entries with no zone and no UTC marker are left exactly as the feed wrote them, which is correct: those are already local wall-clock times. If an entry is still out after this, the /cal zone column says which one to look at.

Your browser does not support Web Serial — use Chrome or Edge on desktop. Web Serial needs HTTPS (this page is) and a direct connection.
