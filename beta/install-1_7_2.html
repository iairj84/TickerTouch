TickerTouch — Calendars Outside Your Timezone

Version 1.7.2 — this is not the default firmware.

An event scheduled by someone in another timezone arrives stamped with that zone. The panel was converting those using a short fixed list of zones, and anything not on the list was silently treated as local time — so exactly the entries created by people elsewhere came out shifted, while everything else stayed correct.

The feed now describes its own zones. Calendar files carry a VTIMEZONE block for every zone they use, with the real offsets and the daylight-saving dates, and that is now what the conversion uses. A zone the firmware has never heard of — a company-specific one, a Windows name, a half-hour offset — converts correctly because the feed defines it. The built-in list is still there for feeds that name a zone but ship no block.

Keep your settings: this installer asks whether to erase the device before flashing. Leave erase off — erasing wipes the WiFi credentials, city and league selection, both calendar URLs and the icon choices.

What to check after installing
  • The work calendar's out-of-zone meetings should now match your phone.
  • Entries you created yourself should not move.
  • If anything is still out, open /cal and read the zone on that block.
An unknown zone is left exactly as the feed wrote it rather than guessed at, so a wrong entry is now visible on /cal rather than hidden behind an assumed offset.

/diag still reports the panel's own zone and offset, which is a separate setting under Display → Timezone if the IP lookup ever gets it wrong.

Your browser does not support Web Serial — use Chrome or Edge on desktop. Web Serial needs HTTPS (this page is) and a direct connection.
