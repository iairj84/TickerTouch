TickerTouch — The Portal Stopped Resetting Settings

Version 1.10.0 — beta. Stable is 1.9.4.

A WiFi re-save was eating your theme and leagues. When the board cannot join a network at boot it falls back to its own setup page. That page's save handler wrote theme and the league bitmask unconditionally — and since the page has no theme field, the empty value became 0, which is Dark; and its league boxes are static defaults with NBA, NHL and MLB pre-ticked, so submitting replaced your selection with those three.

City, coordinates and both calendar URLs sat behind "only if this field was filled in" checks, which is why they survived. The result looked like a partial memory loss: some settings intact, some back to defaults, WiFi asking to be set up again.

Keep your settings: the installer asks whether to erase the device. Leave erase off — erasing wipes WiFi, city, leagues, both calendar URLs and the icon choices.

What was fixed
  • The theme is only written when the submitted form carries one.
  • Leagues are only taken from that page on a genuine first setup. A repeat visit — the WiFi re-save that caused this — now leaves them untouched, because its boxes are static defaults rather than your saved selection.
  • Coordinates are only reset when a city is actually submitted, so re-saving WiFi no longer forces a re-geocode.

Your current theme and leagues were already overwritten by the last portal save, so set them once in Settings after installing. Nothing else needs doing.

Your browser does not support Web Serial — use Chrome or Edge on desktop. Web Serial needs HTTPS (this page is) and a direct connection.
