TickerTouch — Calendar Time Fix

Version 1.6.1 — this is not the default firmware.

Calendar entries that arrive from the feed as UTC were being converted to local time with a single fixed offset — the one in force when the device booted. Any event on the other side of a daylight-saving change therefore read an hour out: a summer dinner at 7pm showing as 6pm. This only affected some entries, because events the feed already sends as local time were always correct.

Times now go through the real timezone rules, so every event uses the offset that was actually in force on its own date.

The clock gains from the same fix: it used to stay on the offset captured at boot, so from the moment daylight saving changed it ran an hour off until the next reboot.

Keep your settings: this installer asks whether to erase the device before flashing. Leave erase off — erasing wipes the WiFi credentials, city and league selection, both calendar URLs and the icon choices.

What to check after installing
  • Entries from the second calendar show the hour you expect, summer ones included.
  • Entries from the first calendar are unchanged.
  • The clock still matches your phone.

The zone is taken by name from the same lookup that already set the clock. If the name is not one the firmware knows, it falls back to the previous fixed-offset behaviour rather than guessing. /diag still shows feed health; the boot log reports which zone was applied.

Your browser does not support Web Serial — use Chrome or Edge on desktop. Web Serial needs HTTPS (this page is) and a direct connection.
