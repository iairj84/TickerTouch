TickerTouch — Local Time From The First Frame

Version 1.10.2 — beta. Stable is 1.9.4.

The clock showed UTC for the first seconds after boot — and the panel dimmed because of it. Nothing sets a timezone until the boot-time IP lookup answers, so localtime() reported UTC for the first second or two. The dashboard is painted before that, and its 10-second timer meant the wrong string stayed on screen. The night window is read the same way, so the panel could decide it was past bedtime at two in the afternoon.

The saved timezone is now installed before the dashboard is drawn: your chosen zone with its daylight-saving rules if you set one, otherwise the UTC offset the last lookup stored. A first-ever boot has neither, so it behaves as before, and the lookup still overrides with the real zone once it answers.

Keep your settings: the installer asks whether to erase the device. Leave erase off — erasing wipes WiFi, city, leagues, both calendar URLs and the icon choices.

What to check after installing
  • On reboot, the header clock reads local time immediately — no UTC flash.
  • The panel does not dim at boot unless it is genuinely inside your night window.
  • Serial prints [TZ] boot: … before the dashboard appears.
  • Travelling, or a DST change, still corrects within one brightness check.

The offset is now saved alongside the rest of the config, which is what makes the boot paint correct even with the timezone left on Automatic.

Your browser does not support Web Serial — use Chrome or Edge on desktop. Web Serial needs HTTPS (this page is) and a direct connection.
