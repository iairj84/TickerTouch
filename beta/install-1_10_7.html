TickerTouch 1.10.7 — Finance That Reloads

Version 1.10.7 — beta. Stable is 1.10.6.

Stocks asked Yahoo one question per symbol, four times a minute. The chart endpoint takes a single ticker per request, so four symbols meant four separate TLS handshakes to the same host every 30 seconds — over two thousand an hour from one home IP. Every other feed uses a different host (ESPN, Open-Meteo, CoinGecko, the calendar), which is why Finance alone went dark while everything else kept loading.

Spark answers the whole symbol list in a single request, needs no crumb (the quote endpoint answers 401 without one), and carries the price and the day's percent change per symbol. The board now makes one request per cycle instead of four, retries once against the other Yahoo edge host if the first refuses, and logs the outcome for every symbol — so a refusal shows up as a status code in the serial log instead of an empty tab.

What was ruled out. The tickers are all valid: SPY, NWPX (Northwest Pipe), COLM and CRMD each answer normally, so nothing about the symbol list was the problem. What stopped was the request path to the chart endpoint, all four at the same moment, while other hosts kept working. That is a property of the endpoint and the board's traffic to it, not of the watchlist.

Keep your settings: the installer asks whether to erase the device. Leave erase off.

What to check
  • Finance populates within about thirty seconds of boot.
  • Serial shows one [Stocks] SYM $price +x.xx% line per symbol, then [Stocks] done: 4.
  • /diag Finance row reads 4 items with a recent age and no failed count.
  • If it is still empty, the serial line [HTTP] 429 <- https://query*.finance.yahoo.com/… (or 401, or -1 for a connection that never completed) names the actual reason — send that one line and it is unambiguous.
